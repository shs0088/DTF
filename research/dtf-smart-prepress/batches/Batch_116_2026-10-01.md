## New materially distinct pages read

1573. https://github.com/tszaks/pixel — Pixel open-source image-cutout and upscaling implementation documentation. Read directly. It routes flat logos/icons, smooth backgrounds and photographic sources through different strategies; preserves enclosed same-color details for logo mode; distinguishes final-quality transparent-image super-resolution from deterministic preview resizing; exposes machine-readable analysis/upscale provenance and explicit alpha/dimension verification. Engineering transfer: Smart Prepress should route by artwork class rather than a universal remover, preserve enclosed negative-space/detail semantics explicitly, distinguish preview resampling from reconstruction-grade SR, and require post-transform alpha/dimension checks. Hosted long-running enhancement should not be treated as an ordinary synchronous request.

1574. https://gameimagekit.com/en/tool/ai-matting — GameImageToolkit browser matting documentation. Read directly. It separates General/RMBG, Portrait/MODNet and click-guided SlimSAM modes, keeps click-to-cut at original canvas size, uses WebGPU with WASM fallback, supports manual eraser correction and runs locally. Engineering transfer: record model family, interaction mode, backend and canvas transform in matte provenance; backend fallback is not assumed numerically identical; user edits must become explicit matte-edit provenance rather than silently overwriting the model result.

1575. https://docs.opencv.org/5.0/tutorials/app/video_input_psnr_ssim.html — OpenCV PSNR/SSIM implementation tutorial. Read directly. PSNR derives from MSE and is cheap but can disagree with perceived structural quality; SSIM evaluates local mean/variance/covariance using Gaussian windows and is more computationally expensive. Engineering transfer: use cheap global metrics only as a first regression screen, then structural metrics for suspicious transforms. For DTF, neither metric is sufficient alone: alpha-boundary displacement, topology, minimum-feature survival, color difference and physical printability remain separate gates.

## Engineering synthesis
1. Add an explicit `ArtworkClass` router before background removal: `FLAT_LOGO | SMOOTH_BG | PHOTO | PORTRAIT | CLICK_GUIDED | KNOWN_BG | DUAL_PLATE`. The remover/matting strategy should be selected from evidence about the source, not from one universal model.
2. Add `MatteProvenance = model_family + model_version + interaction_mode + backend + precision + input_transform + output_transform + manual_edit_history`. WebGPU/WASM or other backend fallback must be observable and regression-tested rather than assumed identical.
3. Preserve negative-space/enclosed-detail semantics explicitly for logos and icons. Edge-connected background removal must not erase enclosed same-color artwork merely because its RGB resembles the removed background.
4. Split `PreviewResize` from `ReconstructionUpscale`. A cheap deterministic resize is acceptable for UI previews, but a learned SR/reconstruction path changes evidence and therefore invalidates effective-DPI, edge, glyph/topology, minimum-feature, choke and screening calibration until re-preflighted.
5. Add tiered regression QA: cheap pixel-domain screening (MSE/PSNR) can identify obviously changed outputs; structural similarity can detect broader structural changes; DTF acceptance still requires domain metrics for alpha edges, connected components/holes, glyph topology, minimum physical stroke/dot, color delta, white-underbase geometry and print-profile limits.
6. Never use PSNR/SSIM as a printability authority. A high similarity score can coexist with a one-pixel alpha displacement that becomes a visible white halo, or with loss of a small isolated feature that fails transfer.
7. For async enhancement, persist immutable input hash, requested transform, provider/model/version, job ID, final geometry and verification results. Long-running SR should be an async job boundary; synchronous HTTP waiting is a deployment risk, not a quality guarantee.
