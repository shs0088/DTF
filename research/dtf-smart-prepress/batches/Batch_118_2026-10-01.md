## New materially distinct pages read

1582. https://photomop.com/glossary/image-matting — Image-matting technical explainer, read directly. It distinguishes binary segmentation from continuous alpha plus foreground-color estimation, explains the under-constrained compositing equation, and identifies foreground-color decontamination/spill suppression as necessary to prevent retained background tint. It also notes that tight trimaps localize uncertainty better than broad unknown bands. Engineering transfer: matte QA must evaluate both alpha geometry and reconstructed foreground RGB; trimap uncertainty-band width should be recorded and excessive uncertainty should be a diagnostic signal.

1583. https://github.com/cmw2004/Portrait-Matting-with-U-Net — Open-source portrait-matting implementation, read directly. It uses a ResNet18 U-Net/attention architecture with a composite objective combining BCE, L1, Laplacian edge loss and Sobel gradient loss; inference emits grayscale matte, RGBA cutout and composite preview, with optional edge smoothing. Engineering transfer: global matte error is insufficient for DTF; edge/gradient objectives and metrics should be first-class, and any post-inference smoothing must be separately provenance-tracked because it changes print geometry.

1584. https://yuustudio.app/ja/tools/background-remover — Japanese browser-local RMBG-1.4 background-removal implementation documentation, read directly. It runs foreground-mask inference through WebGPU or WASM, accepts bounded file/megapixel inputs, preserves original-resolution PNG output, exposes edge smoothing/feather/sharpness and manual brush/lasso restore/erase, and previews against transparent/white/black/custom backgrounds. Engineering transfer: manual correction must be represented as an edit layer/history rather than destroying model provenance; runtime fallback and edge-control settings need persistence; multi-background preview should be mandatory QA.

1585. https://webpforge.com/remove-background — Browser color-key background-removal implementation, read directly. It uses Euclidean color-vector similarity with adjustable tolerance and gradient feathering around contours rather than semantic AI segmentation. Engineering transfer: add a deterministic `COLOR_DISTANCE_KEY` route for logos/studio images with genuinely uniform backgrounds; persist target/background color, color space/distance definition, tolerance and feather width, and reject this route for foreground colors that collide with the keyed background.

1586. https://smallpngtools.com/generate-png-alpha-mask.php — Browser alpha-mask generation implementation, read directly. It supports multiple picked background colors, threshold and smoothing and exports a grayscale matte where gray represents partial transparency. Engineering transfer: multi-key color removal should be modeled separately from semantic segmentation; threshold and smoothing are independent operations, and a generated matte must retain continuous grayscale unless an explicit binary-mask authority is requested.

## Engineering synthesis
1. Expand matte authority from `alpha-only` to `MatteArtifact = alpha + foreground-RGB estimate + uncertainty provenance`. A visually plausible alpha with contaminated foreground RGB can still produce colored fringes on garment/mockup backgrounds.
2. Add explicit edge-focused matte QA: boundary MAE/gradient agreement, edge displacement, fractional-alpha occupancy and multi-background fringe tests. Global MAE/IoU cannot certify DTF edge quality.
3. Preserve manual correction as non-destructive provenance: model/backend/version → inferred matte → edge-control transform → brush/lasso edit layer → final matte. This permits reproducibility and later re-running a newer model without losing operator edits.
4. Add deterministic `COLOR_DISTANCE_KEY` as a routing option for genuinely uniform studio/logo backgrounds. Store color space, key color(s), distance metric, tolerance, feather/smoothing and collision-risk diagnostics. It should not silently replace semantic segmentation or matting.
5. Treat thresholding and smoothing as separate mask transforms. Threshold changes membership/coverage authority; smoothing changes boundary geometry. Both require independent settings, before/after alpha histograms and topology/minimum-feature QA.
6. Runtime fallback (WebGPU/WASM/CPU/GPU) and any resize performed for model input must remain in provenance. Final export at source resolution does not prove that the inference itself operated at source resolution.
