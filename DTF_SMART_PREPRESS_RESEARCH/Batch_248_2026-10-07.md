## Engineering synthesis additions
1. **Model the RIP as a transformation profile, not a passive output device.** Modern DTF RIPs can own white generation, white floor/boost, choke, halftoning, ICC conversion and native nozzle/PRN rasterization. Smart Prepress therefore needs an explicit `RIPProfile` declaring which transformations are owned upstream versus downstream to prevent duplicate screening, resizing or color conversion.
2. **Lock physical size before halftone generation.** LPI/grid density and dot spacing are physical properties. Resizing a pre-halftoned bitmap changes the effective screen and minimum dot size. Store `halftone_physical_scale_locked=true`; if a RIP owns screening, preserve the Ready-to-Print master as continuous tone.
3. **White-edge policy must be explicit.** A hard-threshold white mask and a soft alpha-derived white mask behave differently around antialiased/fractional-alpha edges. Store `white_edge_mode = hard|soft|rip_native`; never silently quantize continuous alpha merely to create underbase.
4. **Choke/spread require post-operation survivability QA.** Excessive inward contraction can erase serifs, hairlines and small halftone islands. Recompute local feature thickness and connected components after simulated choke, reporting `feature_survival_ratio` and `post_choke_min_feature_mm`.
5. **Adaptive choke should be evidence-driven.** Mixed gang sheets contain logos, text, photos and distressed/halftone art with very different feature scales. A single global erosion radius is unsafe. Use physical-unit choke constrained by local thickness/topology and the calibrated output condition.
6. **Preserve a clean handoff boundary.** If native RIP output avoids an extra resampling stage, upstream Smart Prepress should deliver exact final pixel dimensions, physical placement and ICC provenance, then avoid an unnecessary second raster resize.
7. **Vendor choke numbers remain calibration priors, not standards.** Different sources publish materially different px/mm/pt recommendations. Store them only as test starting points; the production threshold must come from printer/ink/film/powder/RIP calibration.
8. **Browser-local processing is a useful security architecture for optional tools.** Halftone/preflight previews that can run locally reduce upload exposure, but server-side production still requires independent decode/validation and resource limits when a master is submitted.
