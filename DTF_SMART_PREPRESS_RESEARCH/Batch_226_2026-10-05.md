## Engineering synthesis
- Transparent pixels' hidden RGB is an active resampling hazard. Edge decontamination/extension width must be related to the resampling kernel support: a width sufficient for bilinear can be insufficient for bicubic, Lanczos, or downsampling.
- Alpha-aware RGB extension should weight candidate colors by alpha rather than treating fully opaque and semi-transparent contributors equally. This belongs in edge-decontamination provenance.
- Alpha representation is pipeline metadata, not merely a file property. Mislabeling premultiplied pixels as straight can darken translucent edges; treating straight RGB as premultiplied can create bright fringes. Normalize representation at pipeline boundaries and test translucent-edge fixtures.
- A full-resolution output PNG does not prove full-resolution inference. If a matting model works on a resized image and only upsamples the matte, record model-input dimensions, matte-native dimensions, upscale ratio/kernel and source dimensions; use this for confidence scoring around fine text/hair/thin structures.
- Model routing should be domain-aware. A portrait matting model that performs well on people can be unreliable for products, pets, graphics, and busy objects; route or downgrade confidence rather than presenting all masks as equivalent.
- Halftone acceptance must be output-process aware. Minimum highlight dots can disappear and high-coverage shadow openings can close; LPI/mesh/process capability and minimum stable feature must be calibrated instead of hard-coded as universal DTF constants.
- For DTF Studio, add a post-resize transparent-edge QA stage that composites on light, dark, and saturated backgrounds and checks RGB fringe energy separately from alpha geometry.
