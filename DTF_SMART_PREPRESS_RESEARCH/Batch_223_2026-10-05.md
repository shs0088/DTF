## Engineering synthesis
- White-underbase generation must distinguish opaque artwork from semi-transparent gradients. A geometric choke alone can fix registration halo on opaque edges but can destroy intended translucency when white is generated beneath fractional-alpha pixels. Add white_support_policy with modes such as binary-support, alpha-weighted-support, color/luminance-conditioned support, plus explicit semi-transparent-edge QA.
- Keep white density separate from white-support eligibility and choke geometry. Density changes ink amount where support exists; it is not the same control as deciding which pixels receive white.
- Edge tightening is bilateral: inward edge movement consumes a thin stroke from both sides. Prepress must estimate local feature width before tighten/choke and reject or reduce operations that would erase thin text, dots, distressed islands, counters, or halftone structures.
- Deblur, sharpening and upscaling solve different failure modes. Deblur should precede upscale when genuine optical/motion blur exists; sharpening increases edge contrast but does not recover missing detail; generative upscale invents plausible detail and must be provenance-labeled rather than treated as recovered source detail.
- White masks should be generated at the final output geometry/DPI. Solid and screened/halftone underbases need distinct QA. Export format and RIP capability must be recorded; a preview PNG is not equivalent to a RIP-ready 1-bit/spot-channel artifact.
- Non-local-means denoising uses patch similarity rather than only local blur. Denoising strength is therefore content-sensitive; excessive denoise can remove print-critical microtexture. Record denoise algorithm/strength and rerun thin-feature/texture survival QA after denoise.

## Pipeline implications
decode -> classify defect/source condition -> background/alpha work -> edge/RGB cleanup -> genuine deblur if justified -> resize/upscale -> final physical sizing -> local feature-width analysis -> white-support qualification -> calibrated choke/spread -> post-choke topology QA -> screening/halftone -> output-condition QA.

No storefront, deployment, merge, or production code changes.
